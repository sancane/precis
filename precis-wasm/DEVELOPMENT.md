# Development Guide for precis-wasm

## Prerequisites

1. **Rust 1.85+**: Required by the workspace (2024-edition dependencies)
2. **wasm-pack**: WASM build tool

Install wasm-pack:
```bash
curl https://rustwasm.github.io/wasm-pack/installer/init.sh -sSf | sh
```

Or via cargo:
```bash
cargo install wasm-pack
```

## Building

### For Web (Browser) - Recommended

```bash
cd precis-wasm
./build.sh
# or
npm run build
```

This script:
1. Builds WASM for both the web and Node.js targets and merges them into `pkg/`
2. Compiles the TypeScript wrappers, which add proper `string → string` types
3. Copies the committed `package.json` (with conditional `exports`) into `pkg/`

Generated files:
- `pkg/precis_web.mjs` / `pkg/precis_web_bg.wasm` - web (ESM) glue + binary
- `pkg/precis_node.js` / `pkg/precis_node_bg.wasm` - Node.js (CJS) glue + binary
- `pkg/precis.mjs` / `pkg/precis.d.mts` - browser wrapper (string types) ✅
- `pkg/precis-node.js` / `pkg/precis-node.d.ts` - Node.js wrapper (string types) ✅
- `pkg/package.json` - NPM metadata with conditional `exports`

### Raw Build (without TypeScript fixes)

```bash
wasm-pack build --target web --out-dir pkg --out-name precis_web
```

Note: This will generate `any` types. Use `./build.sh` for proper TypeScript support.

### For Node.js

```bash
wasm-pack build --target nodejs --out-dir pkg-node --out-name precis_node
```

### For Bundlers (webpack, rollup, parcel)

```bash
wasm-pack build --target bundler --out-dir pkg-bundler
```

## Testing

### Run tests in browser

```bash
# Chrome (recommended; this is what CI uses)
wasm-pack test --headless --chrome

# Firefox
wasm-pack test --headless --firefox

# Safari
wasm-pack test --headless --safari
```

### Run specific test

```bash
wasm-pack test --headless --chrome -- test_nickname_enforce_basic
```

## Development Workflow

1. **Make changes** to `src/lib.rs`
2. **Check compilation**: `cargo check --package precis-wasm`
3. **Run clippy**: `cargo clippy --package precis-wasm -- -D warnings`
4. **Build WASM**: `wasm-pack build --target web`
5. **Test in browser**: Open `examples/web/index.html` in a local server

### Local Server

You need a local server to test due to CORS restrictions:

```bash
# Python 3
cd precis-wasm
python3 -m http.server 8000

# Or use 'serve' (npm install -g serve)
serve -s .

# Then open: http://localhost:8000/examples/web/
```

## Adding New Functions

To add a new WASM-exposed function:

1. Add the function to `src/lib.rs` with `#[wasm_bindgen]` attribute:

```rust
#[wasm_bindgen]
pub fn my_new_function(input: &str) -> Result<String, String> {
    // Implementation using PrecisFastInvocation
    Nickname::enforce(input)
        .map(|cow| cow.into_owned())
        .map_err(|e| format!("{}", e))
}
```

2. Add tests:

```rust
#[cfg(test)]
mod tests {
    use super::*;
    use wasm_bindgen_test::*;

    #[wasm_bindgen_test]
    fn test_my_new_function() {
        assert_eq!(my_new_function("input").unwrap(), "expected");
    }
}
```

3. Rebuild and test:

```bash
wasm-pack build --target web
wasm-pack test --headless --firefox
```

## Bundle Size

`wasm-pack` builds in release mode and runs `wasm-opt` on the binary, which is
the main size reduction today. The current release binary is about **280 KB**
(~112 KB gzipped).

```bash
ls -lh pkg/precis_web_bg.wasm
gzip -c pkg/precis_web_bg.wasm | wc -c
```

> Note: there is **no** size-tuned `[profile.release]` (e.g. `opt-level = "z"`,
> `lto`, `panic = "abort"`) configured. Cargo profiles only take effect at the
> workspace root, so adding one would affect every crate — it is a workspace-wide
> decision, not something that can be scoped to `precis-wasm` alone.

## Publishing to NPM

The publishable package is assembled in `pkg/` by `build.sh` (both target
glues, both TypeScript wrappers, and a clean `package.json` with conditional
`exports`). Publish that directory — do not use `wasm-pack publish`, which would
only publish a single raw target.

```bash
# Login to NPM (first time only)
npm login

# Build and publish in one step
npm run release          # === npm run build && npm publish ./pkg

# ...or do it manually
npm run build
npm publish ./pkg
```

## Troubleshooting

### Error: "wasm-bindgen not found"

```bash
cargo install wasm-bindgen-cli
```

### Error: "imports memory from '...' but it wasn't found"

This usually means the WASM target isn't properly configured. Make sure:
- `crate-type = ["cdylib", "rlib"]` in Cargo.toml
- Using correct wasm-pack target (web, nodejs, bundler)

### Tests don't run

Make sure you have a browser installed:
```bash
# On Ubuntu/Debian
sudo apt-get install firefox

# On macOS
# Firefox should be in /Applications/
```

### CORS errors in browser

You must use a local HTTP server, not `file://` protocol:

```bash
python3 -m http.server 8000
# Then open http://localhost:8000/examples/web/
```

## CI/CD Integration

A `wasm` job in `.github/workflows/rust_checks.yml` already runs on every push
and pull request to `main`. It:

- installs the `wasm32-unknown-unknown` target, `wasm-pack` and Node.js,
- runs the `#[wasm_bindgen_test]` suite in headless Chrome,
- runs `npm run build` to produce the full publishable package, and
- `npm pack`s it into a throwaway consumer and asserts that both `require()`
  (CommonJS) and `import` + `await init()` (ESM) resolve through `exports`.

Automated publishing to NPM on tag is not yet wired up.
